# TokenPulse - 需求文档

## 1. 项目概述

### 1.1 项目名称
TokenPulse - LLM模型诊断工具

### 1.2 项目定位
一套全面的LLM模型诊断工具，类似于医院体检系统，能够对大语言模型进行多维度的健康检查，发现潜在问题并生成诊断报告。

### 1.3 目标用户
- 模型训练工程师：检查训练后的模型是否存在表征坍缩、概率偏斜等问题
- 模型部署工程师：评估模型在部署前的鲁棒性和置信度校准
- 模型研究人员：分析不同架构模型的内在特性
- 企业AI团队：对自研或微调模型进行质量把关

### 1.4 核心价值
- **解耦设计**：推理过程与诊断逻辑分离，扩展性强
- **统一接口**：屏蔽不同推理框架（HuggingFace/vLLM/API）的差异
- **高效复用**：避免重复推理，一次抽取多次诊断
- **可视化报告**：生成人类可读的体检报告

## 2. 功能需求

### 2.1 核心功能模块

#### 2.1.1 模型适配（L1层）
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| HuggingFace适配 | 支持本地HF模型加载，提取logits、hidden_states、attention_weights | P0 |
| vLLM适配 | 支持vLLM高效推理，配置返回中间层激活 | P1 |
| API适配 | 支持OpenAI/Anthropic等API，提取logprobs | P1 |
| 统一输出格式 | 将不同后端输出统一为标准ModelOutput对象 | P0 |

#### 2.1.2 数据缓存（L2层）
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 特征缓存 | 基于Hash的缓存机制，避免重复推理 | P0 |
| 多格式存储 | 支持内存缓存和磁盘存储（HDF5/Zarr） | P1 |
| 张量对齐 | 自动处理Padding、截断，输出纯净张量 | P0 |

#### 2.1.3 核心计算引擎（L3层）
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 信息论工具 | 熵计算、KL散度、交叉熵、Top-P比例 | P0 |
| 线性代数工具 | SVD分解、有效秩计算、余弦相似度 | P0 |
| 校准工具 | ECE（期望校准误差）、Brier Score | P0 |
| 扰动生成器 | 同义词替换、拼写错误注入、无关上下文注入 | P1 |

#### 2.1.4 诊断模块（L4层）

**概率与分布类诊断**
| 检查项 | 描述 | 诊断目的 |
|--------|------|----------|
| 词表利用率检查 | 统计模型实际使用的词表比例 | 发现词表坍缩、输出多样性问题 |
| 无条件熵检查 | 计算模型无条件输出的熵值 | 评估模型的基础不确定性 |
| 概率偏斜检查 | 检测Top-P概率质量分布 | 发现输出过于集中或分散的问题 |

**敏感度与鲁棒性类诊断**
| 检查项 | 描述 | 诊断目的 |
|--------|------|----------|
| 扰动敏感度检查 | 输入微小扰动后观察输出KL散度变化 | 评估模型鲁棒性 |
| 上下文依赖度检查 | 注入无关上下文后观察输出变化 | 发现上下文干扰问题 |

**表征与权重类诊断**
| 检查项 | 描述 | 诊断目的 |
|--------|------|----------|
| 表征坍缩检查 | 分析各层hidden_states的有效秩 | 发现表征退化、训练问题 |
| 注意力沉检查 | 分析注意力权重分布 | 发现注意力模式异常 |

**校准与置信度类诊断**
| 检查项 | 描述 | 诊断目的 |
|--------|------|----------|
| 置信度校准检查 | 计算ECE，对比置信度与实际准确率 | 发现过度自信或自信不足 |
| 幻觉易感性检查 | 分析模型对不确定性的表达 | 预测幻觉产生倾向 |

#### 2.1.5 报告与编排（L5层）
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 体检流水线编排 | 支持并行/串行调度诊断任务 | P0 |
| 健康度评分 | 将原始指标映射为健康等级（绿灯/黄灯/红灯） | P0 |
| 报告生成 | 生成Markdown/HTML格式的体检报告 | P0 |
| 可视化图表 | 绘制各层指标折线图、分布直方图等 | P1 |

### 2.2 非功能需求

#### 2.2.1 性能要求
- 支持流式抽取中间层激活，避免显存爆炸
- 缓存机制确保同一样本不重复推理
- 支持批量样本并行处理

#### 2.2.2 可扩展性
- 新增诊断项只需继承BaseCheck类，无需修改推理代码
- 支持自定义基线模型进行对比

#### 2.2.3 兼容性
- 支持Python 3.9+
- 兼容主流深度学习框架（PyTorch 2.0+）
- 支持GPU和CPU运行

#### 2.2.4 易用性
- 提供预设体检套餐（快速体检/全套深度体检）
- 支持YAML配置文件定制体检项
- 提供命令行接口和Python API两种使用方式

## 3. 用户场景

### 3.1 场景一：模型训练后检查
```
用户：某公司模型训练工程师
目标：检查刚训练完的7B模型是否存在表征坍缩
流程：
1. 加载模型到 TokenPulse
2. 选择"神经内科"体检套餐（包含表征坍缩检查）
3. 运行体检
4. 查看报告，发现第15-20层有效秩明显下降
5. 决定调整训练策略
```

### 3.2 场景二：模型部署前评估
```
用户：某企业AI平台部署工程师
目标：评估模型在生产环境中的鲁棒性
流程：
1. 加载待部署模型
2. 选择"全科体检"套餐
3. 运行体检，重点关注扰动敏感度和置信度校准
4. 发现模型对拼写错误过于敏感
5. 决定在前处理阶段增加拼写纠正模块
```

### 3.3 场景三：API模型诊断
```
用户：使用GPT-4的研究人员
目标：分析API模型的不确定性表达
流程：
1. 配置OpenAI API密钥
2. 选择"浅度体检"套餐（仅使用logprobs）
3. 运行体检
4. 分析置信度校准结果
5. 输出研究报告
```

## 4. 约束与假设

### 4.1 约束条件
- 本地模型需要足够的GPU显存进行中间层抽取
- API模型只能进行浅度体检（无hidden_states）
- 大模型（70B+）需要分布式推理支持

### 4.2 假设前提
- 用户具备基本的Python和深度学习知识
- 用户能够提供合适的测试数据集
- 模型权重可访问（本地模型）

## 6. 分阶段交付计划

### 6.1 P0 阶段：奠基之作

**目标**: 搭好骨架，为后续所有检查提供底座

| 交付物 | 内容 | 验收标准 |
|--------|------|----------|
| TransformerLensProvider | L1 层适配器 | 能够通过统一接口提取 logits/hidden_states/attention |
| calc_entropy | L3 层信息熵函数 | 通过单元测试，支持 batch 计算 |
| calc_kl_divergence | L3 层 KL 散度函数 | 通过单元测试，数值精度验证 |
| calc_ece | L3 层 ECE 函数 | 通过单元测试，输出校准曲线数据 |

**不产出具体体检项，但构成所有后续检查的基础设施。**

### 6.2 P1 阶段：MVP 闭环

**目标**: 形成可演示的最小产品，只需要 Logits 即可运行

| 交付物 | 内容 | 验收标准 |
|--------|------|----------|
| VocabularyUtilizationCheck | 词表利用率检查 | 输出利用率百分比 + 概率分布直方图 |
| TokenStabilityCheck | Token 稳定性检查 | 输出概率标准差 + 高波动区域标记 |
| ConfidenceCalibrationCheck | 置信度校准检查 | 输出 ECE 值 + Reliability Diagram |
| MVP 演示脚本 | 端到端体检流程 | 两个检查项跑通，生成简易报告 |

**MVP 演示闭环**:
- 常规抽血: 空输入 → 词表概率分布 → 发现病态高概率 token
- 心电图: 常识题 → ECE → 校准曲线 → 发现过度自信

### 6.3 P2 阶段：专科检查

**目标**: 深度机理检查，需要中间层激活

| 交付物 | 内容 | 验收标准 |
|--------|------|----------|
| PerturbationGenerator | L3 层扰动生成器 | 支持同义词替换、噪声注入、改写 |
| PerturbationSensitivityCheck | 微扰敏感度检查 | 输出 KL 散度变化 + 鲁棒性评分 |
| AttentionSinkCheck | 注意力沉检查 | 输出首 token 占比 + 注意力熵 |
| RepresentationCollapseCheck | 表征坍缩检查 | 输出有效秩曲线 + 坍缩层标记 |
| L2 缓存完善 | 中间层缓存 | 支持流式落盘，避免显存爆炸 |

### 6.4 P3 阶段：生态扩展

**目标**: 长线能力建设

| 交付物 | 内容 | 验收标准 |
|--------|------|----------|
| API 黑盒校准 | 支持 API 模型校准 | 兼容 OpenAI/Anthropic |
| 知识熵检查 | 微调遗忘研究 | 与 OLMo 模型集成 |
| 训练动态对比 | Checkpoint 对比 | 多时间点健康趋势图 |
| 基线数据库 | 内置参考值 | 主流模型体检指标库 |

## 8. 风险评估

| 风险项 | 影响 | 缓解措施 |
|--------|------|----------|
| 显存不足导致OOM | 无法完成深度体检 | 实现流式抽取与磁盘落盘 |
| API变更导致适配失效 | 部分功能不可用 | 设计灵活的适配器接口，快速响应变更 |
| 诊断指标缺乏基准 | 结果难以解读 | 内置主流模型的基准数据 |
| 计算资源需求大 | 运行时间长 | 优化计算流程，支持采样检查 |
